# Bài thực hành số 3: Dịch vụ quản lý sản phẩm

## 1. Mục tiêu

Xây dựng Product Management service theo kiến trúc SOA. Dịch vụ chạy độc lập
với Auth API trên cổng riêng `3001`, cung cấp REST API CRUD sản phẩm và lưu
dữ liệu trong PostgreSQL Database của Supabase. API yêu cầu access token do
Auth API ở bài thực hành số 2 cấp.

## 2. Công nghệ và cấu trúc

- Node.js 20 trở lên, Express 5.
- Supabase Auth để đăng nhập và xác minh token; Supabase PostgreSQL để lưu sản phẩm.
- Swagger UI / OpenAPI để xem và thử API.
- Node.js test runner để kiểm thử.

| Tệp | Chức năng |
| --- | --- |
| `products-server.js` | Khởi động Product service trên cổng `3001` |
| `products-app.js` | Định tuyến API sản phẩm, Swagger và xác thực |
| `products-controller.js` | Kiểm tra dữ liệu và xử lý CRUD |
| `products-store.js` | Truy vấn bảng `products` trên Supabase |
| `auth-middleware.js` | Xác minh Bearer token với Supabase Auth |
| `app.js`, `server.js` | Auth API của bài thực hành số 2, mặc định cổng `3000` |
| `swagger.js` | Định nghĩa tài liệu OpenAPI cho hai service |
| `test/` | Kiểm thử các API và xác thực |

## 3. Cấu hình Supabase Database

Trong Supabase Dashboard, mở **SQL Editor → New query** và chạy SQL sau để tạo
bảng sản phẩm cùng các policy RLS:

```sql
create table public.products (
  id bigint generated by default as identity primary key,
  name varchar(255) not null,
  description text not null default '',
  price numeric(10, 2) not null check (price >= 0),
  quantity integer not null check (quantity >= 0),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

alter table public.products enable row level security;

create policy "Authenticated users can read products"
  on public.products for select to authenticated using (true);
create policy "Authenticated users can add products"
  on public.products for insert to authenticated with check (true);
create policy "Authenticated users can update products"
  on public.products for update to authenticated using (true) with check (true);
create policy "Authenticated users can delete products"
  on public.products for delete to authenticated using (true);
```

Các policy trên cho phép mọi tài khoản đã đăng nhập đọc và quản lý toàn bộ sản
phẩm. Nếu cần phân quyền theo chủ sở hữu, hãy bổ sung `user_id` và thay policy
cho phù hợp.

Tạo một tài khoản đăng nhập trong **Supabase Dashboard → Authentication → Users**.
Nếu project yêu cầu xác nhận email, hãy xác nhận trước khi đăng nhập.

## 4. Cài đặt và chạy

Mở PowerShell tại thư mục dự án, ví dụ `C:\Users\admin\SOA`:

```powershell
npm install
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

Trong `.env`, điền URL và publishable key của cùng một project Supabase:

```dotenv
PORT=3000
PRODUCTS_PORT=3001
SUPABASE_URL=https://<project-id>.supabase.co
SUPABASE_PUBLISHABLE_KEY=<publishable-key>
```

Khởi động hai service trong **hai cửa sổ PowerShell riêng**, tại thư mục dự án:

```powershell
npm start
```

```powershell
npm run start:products
```

Auth API sẵn sàng tại `http://localhost:3000`; Product service tại
`http://localhost:3001`. Giữ cả hai cửa sổ mở trong khi sử dụng. Cấu hình
`.env` không được commit lên Git; không dùng `service_role` key trong ứng dụng.

## 5. REST API sản phẩm

Mọi request bên dưới đều cần header:

```http
Authorization: Bearer <access-token>
```

| Phương thức | Đường dẫn | Kết quả |
| --- | --- | --- |
| `GET` | `/products` | Lấy danh sách sản phẩm |
| `GET` | `/products/:id` | Lấy chi tiết một sản phẩm |
| `POST` | `/products` | Tạo sản phẩm |
| `PUT` | `/products/:id` | Cập nhật toàn bộ thông tin sản phẩm |
| `DELETE` | `/products/:id` | Xóa sản phẩm |

Body mẫu cho `POST` và `PUT`:

```json
{
  "name": "Keyboard",
  "description": "Mechanical keyboard",
  "price": 79.95,
  "quantity": 12
}
```

`name` là bắt buộc và tối đa 255 ký tự; `description` là tùy chọn; `price`
không âm và tối đa hai chữ số thập phân; `quantity` là số nguyên không âm.
Các trường thời gian được lưu và trả về theo `created_at`, `updated_at`.

Các status chính: `200` khi đọc/cập nhật thành công, `201` khi tạo,
`204` khi xóa, `400` nếu ID hoặc dữ liệu không hợp lệ, `401` nếu thiếu hoặc
token không hợp lệ, và `404` nếu không tìm thấy sản phẩm.

## 6. Đăng nhập và thử API bằng Swagger

Swagger UI:

- Auth API: `http://localhost:3000/api-docs`
- Product API: `http://localhost:3001/api-docs`

Trong Swagger Auth, gọi `POST /login` với email và mật khẩu Supabase:

```json
{
  "email": "student@example.com",
  "password": "your-password"
}
```

Sao chép trường `token` trong phản hồi. Trong Swagger Product, bấm
**Authorize**, dán token (không thêm tiền tố `Bearer`) và xác nhận; Swagger sẽ
tự thêm header xác thực cho các API sản phẩm. Có thể kiểm tra token bằng
`GET /auth` trên Auth API.

Đăng nhập trả access token dạng JWT. Swagger chỉ hỗ trợ gửi token; server xác
minh token với Supabase Auth, không coi việc giải mã nội dung JWT là xác thực.

## 7. Kiểm thử

```powershell
npm test
```

Các bài test dùng Auth client giả lập và không gọi project Supabase thật.

## 8. Lưu ý bảo mật

- Không đưa mật khẩu, access token, hoặc `service_role` key vào mã nguồn hay Git.
- Product service chuyển access token người dùng cho Supabase Database để áp
  dụng RLS; quyền thao tác dữ liệu do policy trong Supabase kiểm soát.
- Khi triển khai ngoài máy cá nhân, cấu hình HTTPS và giới hạn RLS theo yêu cầu
  phân quyền thực tế.
